1. REGRAS DE NEGÓCIO - CATEGORIAS
═══════════════════════════════════════════════════════════════

REGRA #1: MÚLTIPLAS CATEGORIAS POR ANÚNCIO
   • Um negócio/anúncio pode pertencer a MÚLTIPLAS categorias simultaneamente
   • Exemplo: "Feira de Artesanato" pode ser "Eventos" E "Imperdíveis"
   • Campo no BD deve ser ARRAY/LISTA de categorias
   • Tipo: categories: string[] (não category: string)

REGRA #2: CATEGORIA ESPECIAL "IMPERDÍVEIS"
   • "Imperdíveis" é uma categoria de destaque
   • Anúncios marcados como "Imperdíveis" recebem:
     - Badge com borda verde neon (#39ff14)
     - Sombra/brilho visual especial
     - Maior visibilidade na interface
   • Podem ter categoria "Imperdíveis" + outras categorias normais

REGRA #3: FILTROS COMBINADOS
   • Ao selecionar múltiplos filtros, mostrar negócios que tenham 
     QUALQUER uma das categorias selecionadas (OR logic)
   • Se usuário filtrar ["Eventos", "Imperdíveis"], mostrar todos 
     os negócios que tenham "Eventos" OU "Imperdíveis" em suas categorias

3. QUERIES IMPORTANTES
═══════════════════════════════════════════════════════════════

BUSCAR NEGÓCIOS POR MÚLTIPLAS CATEGORIAS (PostgreSQL):
────────────────────────────────────────────────────────────────
SELECT * FROM businesses 
WHERE categories && ARRAY['Eventos', 'Imperdíveis']::text[]
ORDER BY created_at DESC;

-- Operador && verifica se há interseção entre arrays


BUSCAR NEGÓCIOS POR CATEGORIA ESPECÍFICA:
────────────────────────────────────────────────────────────────
SELECT * FROM businesses 
WHERE 'Imperdíveis' = ANY(categories);


INSERIR NEGÓCIO COM MÚLTIPLAS CATEGORIAS:
────────────────────────────────────────────────────────────────
INSERT INTO businesses (
  name, categories, location, cep, phone, whatsapp, 
  description, image, lat, lon, owner_id
) VALUES (
  'Feira Municipal de Artesanato',
  ARRAY['Imperdíveis', 'Eventos'],
  'Centro - Pinhais',
  '83320-100',
  '(41) 98888-0000',
  '5541988880000',
  'Evento especial de artesanato...',
  'https://...',
  -25.4185,
  -49.2130,
  1
);


ATUALIZAR CATEGORIAS DE UM NEGÓCIO:
────────────────────────────────────────────────────────────────
UPDATE businesses 
SET categories = ARRAY['Imperdíveis', 'Eventos', 'Artesanato'],
    updated_at = NOW()
WHERE id = 18;

4. VALIDAÇÕES E SEGURANÇA
═══════════════════════════════════════════════════════════════

CADASTRO DE USUÁRIO:
  ✓ E-mail único no sistema
  ✓ CPF único (11 dígitos, somente números)
  ✓ Senha mínima 6 caracteres (hash bcrypt)
  ✓ Aceitação de termos LGPD obrigatória

LOGIN:
  ✓ Se e-mail não existe → Oferecer cadastro
  ✓ Se e-mail existe mas senha errada → Erro genérico
  ✓ Após cadastro → Redirecionar para login
  ✓ Após login → Redirecionar para tela original (returnTo)

ANÚNCIOS:
  ✓ Mínimo 1 categoria obrigatória
  ✓ Máximo de categorias: ilimitado (recomendado 3-4)
  ✓ Coordenadas lat/lon obrigatórias
  ✓ Imagem obrigatória (URL ou upload)

5. MIGRAÇÃO DE DADOS
═══════════════════════════════════════════════════════════════

CONVERSÃO category → categories:
────────────────────────────────────────────────────────────────
-- Se você tinha campo 'category' singular, migrar para array:

ALTER TABLE businesses 
ADD COLUMN categories TEXT[];

UPDATE businesses 
SET categories = ARRAY[category]
WHERE category IS NOT NULL;

ALTER TABLE businesses 
DROP COLUMN category;

ALTER TABLE businesses 
ALTER COLUMN categories SET NOT NULL;

7. INTEGRAÇÃO FIREBASE (IMPLANTADO)
═══════════════════════════════════════════════════════════════

PROJETO FIREBASE:
  • Nome: achou-android
  • URL Console: https://console.firebase.google.com
  • Autenticação: Email/Password + Google Sign-In (habilitado)
  • Banco de Dados: Firestore (modo produção)

CONFIGURAÇÃO:
  • firebaseConfig.js: Inicializa Firebase na raiz do projeto
  • authService.ts (src/services/): Service layer com funções de auth
  • google-services.json: Configuração Android com SHA-1 registrado

AUTENTICAÇÃO (IMPLEMENTADO):
  • registerWithEmail(email, password, userData)
    - Cria usuário no Firebase Auth
    - Salva perfil em Firestore (collection: users)
    - Retorna { success: true/false, userData?, error? }
  
  • loginWithEmail(email, password)
    - Autentica via Firebase Auth
    - Retorna dados do perfil (Firestore)
    - Retorna { success: true/false, userData?, error? }
  
  • logout()
    - Faz sign out no Firebase
  
  • subscribeToAuthState(callback)
    - Listener para mudanças de autenticação
    - Chamado no AppContext para sincronizar estado
  
  • getUserProfile(uid)
    - Busca dados do usuário em Firestore
  
  • updateUserProfile(uid, data)
    - Atualiza perfil do usuário em Firestore

ESTRUTURA FIRESTORE:

Collection: users/{uid}
  - name: string
  - email: string
  - phone: string
  - cpf: string
  - isPremium: boolean
  - createdAt: timestamp
  - [future fields for profile settings]

Collection: businesses/{businessId}
  - name: string
  - categories: string[] (múltiplas categorias)
  - location: string
  - cep: string
  - phone: string
  - whatsapp: string
  - description: string
  - image: string (URL ou base64)
  - lat: number
  - lon: number
  - instagram: string
  - facebook: string
  - pinterest: string
  - createdBy: string (UID do usuário que criou)
  - createdAt: timestamp
  - updatedAt: timestamp

Collection: users/{uid}/favorites/{businessId}
  - businessId: string
  - addedAt: timestamp
  - [future: notes, rating]

Collection: reports/{reportId}
  - businessId: string
  - reportedBy: string (UID)
  - reason: string
  - description: string
  - status: string ("pending" | "reviewed" | "resolved")
  - createdAt: timestamp

REGRAS DE SEGURANÇA FIRESTORE (PRODUÇÃO):
  • Apenas usuários autenticados podem ler/escrever
  • Usuários só podem editar seus próprios dados
  • Negócios podem ser editados pelo criador
  • Favoritos privados por usuário
